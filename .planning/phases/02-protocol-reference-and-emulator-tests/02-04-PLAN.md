Purpose: ezusb-iidx is the original I/O board used by IIDX 9-19. The protocol is completely separate from ACIO/BIO2 (different USB device, different packet format). Documenting and testing it enables agents to diagnose timing and initialization regressions in older IIDX versions (#344 regression target).

- `src/main/ezusb-iidx/msg.h` — interrupt/bulk packet struct definitions
- `src/main/ezusb-iidx/fpga-cmd.h` — FPGA command and status codes
- `src/main/ezusb-iidx/serial-cmd.h` — serial command codes
- `src/main/ezusb-iidx/node.h` — node ID constants
- `src/main/ezusb-emu/node.h` — node vtable interface

Document structure:
1. Overview — what ezusb-iidx is (Cypress EZ-USB FX2 microcontroller board for IIDX 9-19), completely separate from ACIO/BIO2, different USB device
2. USB Pipe Architecture — interrupt pipe (write: light control + node commands; read: pad state + status), bulk pipe (64-byte page packets for node data)
3. Interrupt Write Packet — complete field-by-field layout of `ezusb_iidx_msg_interrupt_write_packet`, each field's purpose
4. Interrupt Read Packet — complete field-by-field layout of `ezusb_iidx_msg_interrupt_read_packet`, inverted_pad bit positions (P1 keys bits 8-14, P2 keys bits 15-21, panel bits 24-27, sys bits 28-30, coin mode bit 22, board type bit 4, coin mode state bit 31), active-low convention
5. Bulk Packet Format — node + page + 62-byte payload
6. Node Dispatch — `ezusb_iidx_emu_msg_nodes[256]` table, how interrupt write sets cur_node, how bulk read dispatches to cur_node->read_packet
7. FPGA V1 (IIDX 9-13) — init sequence: INIT -> CHECK (0xFF) -> CHECK_2 (0x02) -> WRITE bursts -> WRITE_DONE. Status codes: OK=0x00, OK_2=FAULT=0xFE
8. FPGA V2 (IIDX 14+) — same sequence, cleaner status: INIT_OK=0x41, CHECK_OK=0x42, WRITE_OK=0x43, FAULT=0xFE. fpga2_check_flag_unkn=2
9. Serial Node (V1 only, IIDX 9-13) — H8 framing (CMD_H8_REQ=0xAA, CMD_H8_RESP=0xA5), magnetic card state machine (INIT -> GET_STATUS -> OPEN_SLOT -> card insert -> READ -> GET_STATUS cycle). Note: node-serial.c includes card-mag.c via #include.
10. Other Nodes — SECURITY_PLUG, EEPROM, SRAM, COIN, WDT, 16SEG (brief per-node summary)
11. Board Type Differences — C02 vs D01: bit 4 of inverted_pad behavior (D01 forces bit to 0)

Tag every behavior with confidence markers (Verified/Corroborated/Inferred).
This doc must be completely independent from ACIO/BIO2 docs — no cross-references.
