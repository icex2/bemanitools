  <behavior>
    - GET_VERSION: dispatch request -> response has type=ICCA (0x03000000), version matches configured version enum
    - START_UP: dispatch request -> response status 0x00, fault cleared, polling not started
    - QUEUE_LOOP_START: dispatch -> fault cleared, polling_started=true
    - Poll before queue loop started: POLL -> response indicates fault/not ready (polling hasn't started guard)
    - Poll after queue loop: POLL -> response status indicates idle (no card)
    - Card insert: set eamio-stub sensor state (both front+back sensors) -> poll -> card_result reflects card type, uid matches stub card data
    - Keypad event: set eamio-stub keypad state -> poll -> key_events populated in response
    - Felica version branches: test that v150, v160, v170 each produce different behavior on POLL_FELICA

**Test setup approach — IMPORTANT:**

5. Call `ac_io_emu_icca_dispatch_request` with each crafted message
6. To read responses: the dispatch function queues responses on the emu's `ac_io_in` queue. Use `ac_io_in_drain` to extract response bytes, then parse them back into `struct ac_io_message` format. Alternatively, examine the in queue directly if the struct provides access.
