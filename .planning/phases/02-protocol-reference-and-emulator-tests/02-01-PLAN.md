  <action>
Create `doc/protocol/acio.md` — a comprehensive reverse-engineering reference for the ACIO protocol family. This document must be detailed enough that an agent can write tests against it WITHOUT reading the emulator source code.

Derive the document content by reading these source files:
- `src/main/acioemu/pipe.c` — framing engine (serialize, deserialize, escape, checksum)
- `src/main/acioemu/pipe.h` — struct definitions and API
- `src/main/acio/acio.h` — message struct, command codes, constants, byte-order macros
- `src/main/acioemu/emu.c` + `emu.h` — ACIO emulator IRP dispatch
- `src/main/acioemu/addr.c` + `addr.h` — address assignment logic
- `src/main/acioemu/icca.c` + `icca.h` — ICCA card reader emulator node

Cross-reference with spice2x (https://github.com/spice2x/spice2x.github.io/tree/main) where accessible for confidence elevation.

Document structure (sections in this order):
1. Overview — what ACIO is (serial bus for Konami arcade I/O boards), physical layer (RS232/USB-serial), scope of this doc
2. Wire Frame Format — SOF byte (0xAA), complete byte-by-byte layout table for command messages vs broadcast messages, field descriptions
3. Escape Encoding — escape byte (0xFF), rules for escaping SOF and ESCAPE in payload, exact escape sequences (0xAA -> [0xFF, 0x55], 0xFF -> [0xFF, 0x00])
4. Checksum — which bytes are summed, 8-bit truncation, where checksum appears in frame
5. Autobaud Frame — SOF followed by SOF, yields NULL message
6. Broadcast Messages — addr=0x70, different struct layout (no code/seq_no), when used
7. Response Flag — 0x80 OR'd onto addr for responses
8. Address Assignment — host sends to addr 0 with AC_IO_CMD_ASSIGN_ADDRS, response contains node count, subsequent commands to addr 1..N
9. Legacy Mode — behavior change (drains only one response per cycle), required for popn 15-18 slotted readers, why it exists (old libacio compatibility)
10. ICCA Node State Machine — all ICCA commands (GET_VERSION, START_UP, QUEUE_LOOP_START, SET_SLOT_STATE, POLL, POLL_ENCRYPTED, POLL_FELICA, KEY_EXCHANGE), state transitions, version-dependent behavior (v150/v160/v170), encrypted poll cipher details (Marsaglia KISS PRNG, CRC16-MSB, reader key 0x14243444)
11. Standard Node Commands — GET_VERSION, START_UP, KEEPALIVE (shared across all ACIO node types)

Tag every documented behavior with an inline confidence marker:
- `<!-- [Verified] -->` — code + external source agree
- `<!-- [Corroborated] -->` — code matches at least one external source
- `<!-- [Inferred] -->` — code-only, no external confirmation

Include protocol message examples with hex byte sequences for key operations (address assignment, version query, poll with response).

Create `doc/protocol/` directory if it does not exist.

  <files>src/test/acioemu/Module.mk, src/test/acioemu/acioemu-pipe-test.c, Module.mk</files>
  <behavior>
    - Round-trip: supply raw wire bytes (SOF + addr + code + seq + nbytes + payload + checksum) to ac_io_out_supply, verify ac_io_out_get_message returns correct ac_io_message fields
    - SOF escape: payload containing 0xAA is escaped as [0xFF, 0x55] during serialization (ac_io_in_supply + ac_io_in_drain)
    - ESCAPE escape: payload containing 0xFF is escaped as [0xFF, 0x00] during serialization
    - Checksum validation: wire bytes with wrong checksum -> ac_io_out_have_message stays false after supply
    - Autobaud frame: [0xAA, 0xAA] -> ac_io_out_get_message returns NULL
    - Broadcast message: addr=0x70 -> message parsed with broadcast struct layout (nbytes + raw, no code/seq_no)
    - Truncated frame: SOF appearing mid-frame resets parser state (new frame starts)
    - Response serialization: ac_io_in_supply a message with delay=0, drain into buffer, verify output has SOF + escaped + checksummed bytes
  </behavior>
