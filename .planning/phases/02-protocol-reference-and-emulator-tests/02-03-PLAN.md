Write the BIO2 protocol reference document and create unit tests for the BIO2 IIDX emulator (bio2emu-iidx).

Purpose: BIO2 is the I/O board used by modern IIDX cabinets. The BIO2 emulator wraps ACIO framing with a game-specific command dispatcher. Documenting and testing it enables agents to diagnose I/O regressions in IIDX 20+ (which use BIO2 rather than ezusb).

Output: `doc/protocol/bio2.md` (protocol reference), `src/test/bio2emu/bio2emu-iidx-test.c` (emulator tests), build integration.

Document structure:
1. Overview — BIO2 is ACIO-over-USB-serial, single node at bus address 1. Reference `doc/protocol/acio.md` for framing.
2. Device Architecture — USB serial adapter, how BIO2 port wraps an ac_io_emu struct, single-node topology
3. Address Assignment — addr 0 with AC_IO_CMD_ASSIGN_ADDRS -> response with node_count=1
4. BI2A Command Set — each command with code, request/response format, expected behavior:
   - GET_VERSION -> node type 0x0D060000
   - START_UP -> status 0x00
   - INIT -> status 0x00
   - WATCHDOG -> status 0x00
   - KEEPALIVE -> empty response (nbytes=0)
   - POLL / POLL_WD -> response body is bi2a_iidx_state_out struct
5. Poll State Structs — complete field-by-field documentation of bi2a_iidx_state_in (46 bytes, from game) and bi2a_iidx_state_out (48 bytes, to game), bit positions for all inputs/outputs
6. Poll Behavior — turntable accumulator (TT multiplier mode), coin latch (edge-detect on sys COIN bit), slider defaults from vefx.txt
7. Poll Limiter — Sleep(1) behavior, disable_poll_limiter flag, why it exists
8. Timing Considerations — poll rate, response delay

Do NOT call `bio2emu_port_init()` — it calls `iohook_open_nul_fd()` which requires the iohook subsystem. Instead:
1. Read the source of `bio2_emu_bi2a_dispatch_request` and `bio2_emu_bi2a_init` to determine the minimum struct initialization needed
2. Zero-initialize the `struct bio2emu_port` and any required sub-fields
3. Call `bio2_emu_bi2a_init` with `disable_poll_limiter=true` if it doesn't require iohook
4. If `bio2_emu_bi2a_init` also requires iohook, construct the dispatch inputs manually and call `bio2_emu_bi2a_dispatch_request` directly with a crafted `struct ac_io_message`
5. To check responses: after dispatch_request, read the response from the ac_io_in queue of the embedded ac_io_emu (use `ac_io_in_drain` or examine the struct directly)

The executor MUST read the source to determine the exact initialization path. The goal is to test the dispatch logic without the I/O subsystem.
